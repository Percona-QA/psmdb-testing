## Potential PSMDB and percona-mongot bugs

These cases concern Percona feature implementations, integrations or Percona-specific tests. A test annotation defect is distinct from a server implementation defect. The audit and percona-mongot implementation hypotheses remain unconfirmed as isolated fork defects.

### Tests

- `dollar_audit_mixed_version_mongods.js` in `multiversion`, `multiversion_future_git_tag` — **Potential Percona audit functionality gap** — The test expects mongos to forward authenticated user/role data and the client-address chain to shard profiler records. The absence of $impersonatedClient was reported in the first all-latest scenario. Percona audit may lack the client-attribute initialization required for this propagation; the hypothesis is code-supported but not locally reproduced. [Report](9.0.4-multiversion-dollar_audit_mixed_version_mongods.md)

- `fcbis-replication.js` in `replica_sets_last_lts` — **Percona-specific test annotation defect** — this Percona FCBIS replication test lacks `multiversion_incompatible`, allowing random 9.0/8.0 members to exercise cross-version physical file copying outside its intended scenario. Add the tag alongside `requires_wiredtiger`; the companion `fcbis_backup_cursor_extend.js` already has both. This is a Percona-owned test defect, not evidence of an FCBIS server defect. The test remains enabled pending the source change. [Report](9.0.4-replica_sets_last_lts-fcbis-replication.md).

- `mongot_indexed_views_upgrade_downgrade.js`, `ranked_fusion_on_search_view.js` in `mongot_community_fixture_e2e_sharded_collections`, `mongot_community_fixture_e2e_single_node` — **Percona-mongot deletion-visibility race** — drop is acknowledged and the index listing is empty before query-catalog removal completes. The first test resolves a deleted vector index and rejects `$search`; the second compares equivalent aggregations across that transition and returns 28 versus 10 documents. Post-drop delay controls pass. The first test is excluded only in single-node; the second in both suites. Clarify deletion readiness or fix catalog invalidation. [Report](9.0.4-percona-mongot-index-deletion-visibility.md).

## Disabled: established reasons

### Suites

- `*last_patch*` — **Missing previous-patch binary** — The multiversion fixture needs a binary for the release alias `last-patch`. This setup targets the first 9.0 release and supplies no previous 9.0 patch binary, so the required old/new pair cannot be installed. This is a version-artifact prerequisite rather than a missing server module.

- `aggregation*_fuzzer*`, `generational_fuzzer`, `initial_sync_fuzzer*`, `jstestfuzz*`, `resharding_fuzzer*`, `rollback_fuzzer*`, `sharded_collections_query_shape_hash_stability_*_fuzzer_*`, `update_fuzzer*` — **Closed generated-test corpus** — Setup in `evergreen/jstestfuzz_setup.sh` requires the closed repository `https://github.com/10gen/jstestfuzz`. The generated workload paths, such as `jstestfuzz/out/*.js`, are not supplied by the server checkout. Without access to that repository and its generation step, the selectors cannot obtain their required test corpus.

- `benchmarks_*`, `libfuzzer`, `unittests_*` — **Separate C++ build workflow** — These require separate C++ build artifacts rather than only mongod/mongos: for example `bazel-bin/install/install-mongo_fuzzer_test_test_list.txt` plus its fuzz executables, and benchmark manifests such as `bazel-bin/install/install-first_half_bm_test_list.txt`. They are outside the normal server regression build workflow. Only the requested base `unittests` entry is retained; other unit-test entries are not additional JS regression coverage.

- `buildscripts_test`, `pretty-printer-tests`, `query_tester_self_test`, `resmoke_end2end_tests`, `resmoke_validation_tests` — **Tooling outside binary regression scope** — These entries validate Python resmoke/build tooling, debugger pretty printers or the query-tester harness itself. They depend on tooling-specific setup and do not exercise the released server binaries targeted by this regression list, so they are outside its scope.

- `change_streams_sharding_fsm_*irs*`, `sharding_change_streams_ignore_removed_shards` — **Default-off feature requirement** — These scenarios request ignoreRemovedShards behavior, which requires featureFlagChangeStreamReaderV2. The flag is off in the regular regression binaries, so the requested behavior is unavailable and the tests cannot exercise their intended path. Pairwise variants have no eligible tests under these defaults. SERVER-135099 is the related dependency context.

- `concurrency_compute_mode` — **Empty selector** — Its maintained selector has no runnable workload because the compute-mode workload is disabled under SERVER-112530. Leaving the suite enabled would produce no regression coverage rather than validate compute-mode behavior.

- `concurrency_replication_for_backup_restore`, `concurrency_replication_for_export_import` — **Missing external-cluster prerequisite** — Both suite definitions require `ExternalFixture` and an already running cluster supplied through `--shellConnString` or `--shellConnPort`. The standard invocation provides neither external cluster nor connection argument, so these workloads have no target topology. The missing prerequisite is external deployment setup, not a missing PSMDB backup implementation.

- `cwrwc_wc_majority_passthrough`, `write_concern_majority_passthrough` — **Test/causal-visibility mismatch** — These passthroughs change write concern to majority while tests may subsequently read from secondaries without a causal/read-concern guarantee that makes the write visible there. Assertions can then observe stale data even though the write met its configured acknowledgement requirement. SERVER-89135 tracks the passthrough issue; preserve the distinction between a test consistency assumption and a server majority-write defect.

- `ese*` — **Unavailable upstream module/helpers** — The `ese` selector requires `src/mongo/db/modules/*/jstests/encryptdb/*.js`, and ESE fixture overrides require `src/mongo/db/modules/enterprise/jstests/encryptdb/libs/ekf2`. The upstream Enterprise module containing those tests/key helpers is absent, so the suite has no selected tests or cannot prepare its key file. Percona encryption does not supply this upstream harness.

- `external_auth_aws`, `external_auth_oidc*`, `fle`, `fle2_query_analysis`, `sasl`, `sasl_windows_cyrussasl` — **Unavailable upstream test modules** — Missing upstream Enterprise test roots: `fle` requires `src/mongo/db/modules/*/jstests/fle/*.js`; `fle2_query_analysis` additionally requires `src/mongo/db/modules/*/jstests/fle2_query_analysis/*.js`; `sasl` and `sasl_windows_cyrussasl` require `src/mongo/db/modules/*/jstests/sasl/` (including `sasl_plugins.js`). External-auth roots are `src/mongo/db/modules/enterprise/jstests/external_auth_aws/`, `external_auth_oidc/`, `external_auth_oidc_azure/` and `external_auth_oidc_gcp/`. These upstream module files are absent, so their selectors cannot provide the intended tests; this does not establish that the corresponding Percona server feature is absent.

- `feature_flag_multiversion` — **Synthetic flags excluded by default** — This is a harness test for synthetic Toaster/Spoon feature flags. Its selected tests are filtered by the default exclusions for those flags, leaving no runnable regression cases. It does not validate a real PSMDB feature under normal defaults.

- `logging_perf` — **Logging-tooling setup requirement** — The suite measures resmoke logging throughput with YesFixture and sleep_test, rather than starting a server workload. It needs explicit synthetic sleep-duration inputs; without them it selects no meaningful regression work for PSMDB binaries.

- `magic_restore_*` — **Unavailable upstream runner** — The `magic_restore_js_test` testcase in `buildscripts/resmokelib/testing/testcases/magic_restore_js_test.py` unconditionally starts `src/mongo/db/modules/enterprise/jstests/hot_backups/libs/magic_restore_passthrough_runner.js`. This file belongs to the unavailable upstream Enterprise module. Even when the selected core JS test exists, the wrapper cannot execute the magic-restore scenario without that runner and its helpers.

- `multitenancy_with_mongoq*` — **Unavailable serverless override** — Both suites import `jstests/libs/override_methods/simulate_mongoq.js` during shell setup. That file is absent from the supplied checkout; without it the shell cannot install the tenant/serverless command-routing override required by these tests.

- `query_correctness_generated_test`, `query_correctness_query_shape_hash_stability_generated_test` — **Closed generated-test corpus** — Setup requires closed repositories `https://github.com/10gen/query-correctness-tests-1`, `https://github.com/10gen/query-correctness-tests-2`, `https://github.com/10gen/query-correctness-tests-3` and `https://github.com/10gen/query-correctness-tests-4`, listed in `src/mongo/db/query/query_tester/tests/test_repos.conf` and fetched by `evergreen/query_tester_test_repo_setup.sh`. The suites select `src/mongo/db/query/query_tester/tests/query-correctness-tests-*/generated_tests/*/`; those corpora cannot be provisioned with the available access.

- `query_golden_disagg`, `query_golden_sharding_disagg` — **Unavailable Atlas fixture/module** — `query_golden_disagg` requires `DisaggReplicaSetFixture`, loaded from the absent `buildscripts/modules/atlas/fixtures` package registered in `buildscripts/resmokeconfig/resmoke_modules.yml`. `query_golden_sharding_disagg` imports the absent `src/mongo/db/modules/atlas/jstests/disagg_storage/libs/disagg_storage_override.js`. The required Atlas implementation is missing, preventing fixture construction or override loading.

- `replica_sets_configsvr_param_jscore_passthrough` — **Shared fixture defect** — The fixture starts mongod with --configsvr but builds a replica-set configuration without configsvr:true. Adding the second member is permanently rejected with error 103, which the fixture retries indefinitely before any test or hook runs. Adding only the missing replica-set option made the control pass; the per-test timeout does not protect this setup loop. [Report](9.0.4-replica_sets_configsvr_param_jscore_passthrough-insert1.md)

- `rseq_kernel_check*` — **Host-kernel environment requirement** — The selectors require the kernel-specific tags `requires_kernel_619` or `requires_kernel_7014`; tests under `jstests/noPassthrough/rseq_linux_compatibility/` also vary `GLIBC_TUNABLES=glibc.pthread.rseq=0/1`. Docker shares the host kernel and does not provision these kernel/glibc combinations, so an arbitrary container run does not reproduce the conditions for SERVER-121912.

- `search`, `search_auth`, `vector_search`, `vector_search_auth` with inMemory — **Persistence/setup incompatibility** — The shared mongot-mock helper restarts shard nodes to set mongotHost. With inMemory, restart loses the replica-set data/state that the test setup expects to survive, causing failures or waits during recovery. The affected tests lack persistence annotations, so selecting them by tags alone does not prevent this incompatible setup. Applies only to the inMemory entries.

- `ssl_linear_macos` — **Unsupported operating-system test** — The test exercises the macOS certificate-store integration and depends on that platform’s APIs and certificate environment. The regression runner is Linux, where those prerequisites and the intended code path do not exist.

- `unittest_shell_hang_analyzer` — **Infrastructure self-test requirement** — The test checks whether the shell/resmoke infrastructure invokes the hang analyzer under the expected task, debugger and core-dump conditions. Outside that environment the relevant analyzer path is skipped, so this entry does not validate the intended behavior in the binary-regression setup.

- `watchdog` — **Missing Charybdefs/FUSE prerequisite** — `jstests/watchdog/lib/charybdefs_lib.js` runs `/data/charybdefs/mongo/control.py` to mount a fault-injecting filesystem and stall I/O. That Charybdefs installation and the required FUSE device/mount access are unavailable in the standard regression container, so the test cannot create the filesystem stall needed to check the watchdog.

### Tests

- Version/engine selectors — **Version/storage requirements** — Newer-FCV and unapplied-backport tags prevent tests from assuming behavior missing from an old binary. Persistence/journaling/WiredTiger tags prevent inMemory runs from selecting tests whose setup or assertions require durable storage. These exclusions apply to the chosen version or engine, not to PSMDB generally.

- `block_replica_set_writes.js` and other `requires_replication` tests in `core_high_yielding` — **Standalone/replication mismatch** — The test issues replication-specific commands, but core_high_yielding starts a standalone mongod. Those commands cannot exercise their required replica-set behavior there, so requires_replication tests are excluded from that suite rather than treated as unsupported PSMDB features.

- `cbr_plan_in_cache_cbr_disabled.js` in `core_repeat_queries` — **Test/runner mismatch** — after replanning, the test expects an inactive cache entry for its first two explicit query iterations, but hidden threefold read execution already activates it. Baseline failed; removing only the repeated-read override passed. Excluded using the generated `does_not_support_repeated_reads` tag; add the same tag to the maintained PSMDB test. [Report](9.0.4-core_repeat_queries-plan_cache_state_assertions.md).

- `computation_hoisting_match_pushdown_pbt.js` — **Test/runner mismatch** — The property checks complete, but a local-only diagnostics block then runs aggregate explain. Transaction passthrough wraps that command in a transaction, where explain is forbidden, producing code 263. Skipping only the diagnostics makes the test pass. Applies to the affected transaction, bulk-write and inMemory variants; the property assertions themselves did not fail. [Report](9.0.4-replica_sets_multi_stmt_txn_jscore_passthrough-computation_hoisting_match_pushdown_pbt.md)

- `doc_validation_invalid_validators.js` in `replica_sets_jscore_passthrough_last_lts_old_new_new`, `replica_sets_jscore_passthrough_last_continuous_old_new_new` — **Old-version compatibility** — the old primaries in the reported runs accept a stored validator using $_internalKeyStringValue, but the newer test expects rejection with error 10131412. The missing parser guard was confirmed in the exact 8.3.11-3 source; the same unexpected-success assertion was reported in both suites. Applicability depends on the old binary revision. [Report](9.0.4-replica_sets_jscore_passthrough_multiversion-doc_validation_invalid_validators.md).

- Tests tagged `does_not_support_multiplanning_single_solutions` in `query_join_optimization_passthrough` — **Test/ranker mismatch** — These tests declare that their assertions depend on ordinary single-solution planning. CBR can invoke trial execution even for a single solution, changing when errors occur or which statistics are available. The suite filters the declared incompatibility; this does not mean every tagged test was individually reproduced.

- `explain_all_plans_execution_stats.js` — **Test/ranker mismatch** — the test requires rejected candidate plans to have nonzero document/key counts from multiplanner trial execution. The suite forces CBR, whose explain output reports zero for those trial counts, so the test’s multiplanner-specific assertion fails. [Report](9.0.4-query_join_optimization_passthrough-explain_all_plans_execution_stats.md). Applies to query_join_optimization_passthrough with CBR/samplingCE.

- `explain_execution_error.js` in `query_join_optimization_passthrough` — **Test/ranker mismatch** — the test deliberately exceeds the sort memory limit and expects explain planning to succeed, with the execution error recorded inside executionStats. With this suite’s CBR configuration, the error occurs during plan selection and fails the explain command itself, violating the test’s assumed error-reporting stage.

- `explain_winning_plan.js` in `query_join_optimization_passthrough` — **Test/ranker mismatch** — the test expects the multiplanner to execute candidate plans during its trial period and report 101 returned documents in explain statistics. This suite forces cost-based ranking (CBR), where those trial statistics report zero. The assertion depends on multiplanner behavior and is incompatible with the suite’s intended ranker.

- `explain_with_backup_plans.js` in `query_join_optimization_no_passthrough_with_mongod` — **Test/ranker mismatch** — the test requires classic multiplanner trial scoring and backup-plan selection, while the suite forces cost-based ranking. Its forceClassicEngine setting does not restore multiplanner ranking. This is a configuration incompatibility identified from code; the test was not executed. [Report](9.0.4-query_join_optimization_no_passthrough_with_mongod-planner_prerequisites.md).

- `expr.js` in `query_join_optimization_passthrough` — **Test/ranker mismatch** — the test deliberately uses invalid $divide operands and expects a successful explain response containing the error in executionStats. Under this suite’s CBR configuration, evaluation fails during plan selection, so the explain command returns TypeMismatch before those statistics can be checked.

- `extensions_query_stats.js` — **Shared source defect** — The test hashes a collection name with the shell HMAC helper, then uses that name to filter transformed $queryStats entries. Argument evaluation in the helper turns the supplied non-empty key into an empty key in the tested binary; the wrong hash matches zero entries instead of eight. Independent keyed HMAC makes the test pass. The faulty helper code is shared with matched upstream. [Report](9.0.4-extensions_standalone-extensions_query_stats.md)

- `extensions_signature_pub_key_path.js` — **Test/setup mismatch** — The test expects resmoke to add an extension-signature public-key path to server startup. The configured extension setup uses --skipExtensionsSignatureVerification, which makes the resmoke helper deliberately omit that path. The assertion therefore conflicts with this signature-skipping setup even though the extensions can load.

- `find_with_resume_after_param.js` in `query_join_optimization_passthrough` — **Test/ranker mismatch** — the test expects queryPlanner explain to succeed even when the requested resume RecordId is missing. Under this suite’s CBR configuration, plan selection accesses that RecordId and returns KeyNotFound immediately, so the expected successful explain response is not produced.

- `fle2_string_preview_deprecation.js` — **Closed test dependency** — `EncryptedClient` in `jstests/fle2/libs/encrypted_client_util.js` calls `assertEnterpriseShell()`, which requires `buildInfo().modules` to include `enterprise`. The supplied PSMDB shell lacks that upstream module; the corresponding upstream build target is `src/mongo/db/modules/enterprise/src/fle/shell:implicit_encrypted_dbclient` in the shell BUILD file. The test therefore stops before its upgrade checks. Applies to multiversion/auth and future_git_tag variants.

- `fle2_string_search.js` — **Closed test dependency** — The test creates `EncryptedClient` from `jstests/fle2/libs/encrypted_client_util.js`, whose `assertEnterpriseShell()` rejects a shell without the `enterprise` module. That shell-side implementation comes from `src/mongo/db/modules/enterprise/src/fle/shell:implicit_encrypted_dbclient`, unavailable in this build. Downloading an old mongod does not add the missing client module. Applies to multiversion/auth and future_git_tag variants.

- `initial_sync_replSetGetStatus.js` in `replica_sets_last_continuous` — **Old-version compatibility** — secondary 8.3.11-3 interprets initialSync: 2 as a request for full initial-sync statistics, while the test requires the newer summary response. Reproduced failure: missing collectionsToClone. Secondary 9.0.4-1 passes; the regression list adds the missing backport exclusion. [Report](9.0.4-replica_sets_last_continuous-initial_sync_replSetGetStatus.md).

- `internal_search_id_lookup_ddl_concurrency.js` — **Feature-flag/test annotation** — The test asserts metrics specific to optimized search ID lookup, but does not declare its dependency on featureFlagSearchOptimizedIdLookup. That flag is off in regular binaries, so fallback execution violates those assertions. The generated tag excludes the test under default flags; the maintained test needs the missing dependency annotation.

- `invalid_wildcard_index_log_at_startup.js` — **Missing exact binary** — The test explicitly launches mongod-8.0.16 to check behavior of that exact release. The configured downloader supplies the aliases 7.0, 8.0 and 8.3, which do not provide the requested executable name. The test cannot start its required server unless the exact binary is provisioned; a current 8.0 alias is not an equivalent prerequisite.

- `plan_cache_distinct.js` in `core_repeat_queries` — **Test/runner mismatch** — the test expects its first distinct query to create an inactive cache entry; the suite executes that query three times and the entry is already active. Baseline failed and the override-free control passed. Excluded using the generated `does_not_support_repeated_reads` tag; add the same tag to the maintained PSMDB test. [Report](9.0.4-core_repeat_queries-plan_cache_state_assertions.md).

- `resume_query_from_non_existent_record.js` in `core_minimum_batch_size` — **Test/batch-size mismatch** — the test expects four remaining documents in an unspecified first batch, but this suite deliberately defaults find batch size to two. Reproduced assertion: expected 2 to equal 4. [Report](9.0.4-core_minimum_batch_size-resume_query_from_non_existent_record.md).

- `update_lookup_batching_resume.js` — **Test/config mismatch** — The test waits for its resume token to reach a captured cluster time. In the affected secondary-read suites, periodic no-op writes are deliberately disabled, so the committed oplog can stop before that time and the assertion expires. ## Enabled: detailed investigation required


### Tests

- `balancer_should_return_random_migrations_failpoint.js` in `sharding_config_shard` — **Flaky test; parameter-overwrite hypothesis** — a failure was reported, while the unchanged local run passed in 151.99 seconds. Config-shard startup discards the test’s zero-valued migration settings; the resulting slower migrations may affect tracking/placement assertion deadlines. Resmoke supplies 5000 ms, so migrations are not blocked by the duration guard. The timing hypothesis remains unconfirmed; the test stays enabled. [Report](9.0.4-sharding_config_shard-balancer_should_return_random_migrations_failpoint.md).


- `check_async_oplog_sampling_truncates_new_writes.js` in `no_passthrough` — **Unresolved truncation/timing** — After sampling completes and additional writes create 50 truncate markers, the test still finds a document that should have been removed from the 1 MB oplog and reaches its 90-second assertion deadline. No successful truncation was observed. Inspect the pinned oplog boundary and cap-maintainer wakeup state; neither a missing wakeup nor a server defect is yet proven. [Report](9.0.4-no_passthrough-check_async_oplog_sampling_truncates_new_writes.md)

- `defragment_large_collection.js` in `sharding` — **Unresolved shared migration path** — Defragmentation repeatedly attempts a migration that the recipient rejects because committing it would discard still-reachable point-in-time ownership history for a partially overlapping chunk. The policy reconstructs its phases and repeats the conflict until the assertion expires. Determine how the policy can converge while preserving that history; a larger timeout is not a validated fix. [Report](9.0.4-sharding-defragment_large_collection.md)

- `draining_on_FCV_transition.js` in `multiversion` — **Shared test/protocol defect** — The test pauses setFCV, creates a prepared transaction and expects LockTimeout when setFCV resumes. Under default Symmetric FCV, the relevant global-lock barrier has already executed before that pause, so the new transaction cannot block it and setFCV succeeds. The baseline fails and disabling only Symmetric FCV makes the complete control pass; fix the shared test’s synchronization point. [Report](9.0.4-multiversion-draining_on_FCV_transition.md)

- `fcbis-replication.js` in `replica_sets_last_lts` — **Missing multiversion exclusion tag** — random 9.0/8.0 members introduce cross-version physical WiredTiger copying into an FCBIS replication test. Add `multiversion_incompatible` alongside `requires_wiredtiger`; the companion `fcbis_backup_cursor_extend.js` already has both. The test remains enabled pending the source change. [Report](9.0.4-replica_sets_last_lts-fcbis-replication.md).

- `join_costing_invariants.js` in `query_join_optimization_no_passthrough_with_mongod` — **Unresolved planner/test invariant** — The test reads costEstimate from expected join-plan nodes. Two queries fall back to a plan without those fields and produce NaN; another comparison finds unequal costs for supposedly equivalent join permutations. Determine whether optimizer fallback/costing or the test’s invariant is wrong before excluding it or weakening assertions. [Report](9.0.4-query_join_optimization_no_passthrough_with_mongod-planner_prerequisites.md)
