# computation_hoisting_match_pushdown_pbt: local explain diagnostics incompatible with transaction passthrough

## Confirmed outcome

The unmodified test fails in `replica_sets_multi_stmt_txn_jscore_passthrough` after 272.11 seconds. Error 263, `OperationNotSupportedInTransaction`:

```text
Operation not permitted in transaction :: caused by ::
Explain for the aggregate command cannot run within a multi-document transaction
```

The decisive stack points to `jstests/core/query/computation_hoisting_match_pushdown_pbt.js`, inside the `if (!TestData.inEvergreen)` diagnostics, called through `runWithParamsAllNonConfigNodes()`. This is not a property-result mismatch or a timeout. The fixed-seed property section (`seed = 4`, 50 runs, 200 generated queries per run) completed before the incompatible diagnostic block. No property failure/minimization report was emitted.

The diagnostics sample 500 additional pipelines and call `experimentColl.explain().aggregate(...)` to estimate optimization frequency. The transaction passthrough wraps the aggregate command in a transaction, where aggregate explain is forbidden.

## Control

A disposable-container-only copy changed exactly one condition:

```js
if (!TestData.inEvergreen) {
```

to `if (false)`, skipping only the local explain statistics block. All property checks and transaction suite settings remained active. The test passed in 257.38 seconds; setup, oplog/dbHash validation, collection validation and teardown all passed. Both invocations exited normally: baseline 1, control 0. 

PSMDB version: `9.0.4-1`; 2 CPUs, 8 GiB RAM; `--jobs=1 --testTimeout=1200 --storageEngine=wiredTiger --storageEngineCacheSizeGB=0.25`. Only this named test was executed, with one same-test control. The inMemory and bulk-write variants were not executed.

## Evergreen comparison

The matching checkout's `evergreen/resmoke_tests_execute.sh` passes `--taskId`; `buildscripts/resmokelib/core/programs.py` sets `TestData.inEvergreen=true` when an Evergreen task ID is present. Therefore this diagnostic block is skipped under that launcher. Jenkins regression does not ordinarily provide the Evergreen task metadata and reaches the block.

Exact task/variant inclusion and additional flags cannot be confirmed: referenced `etc/evergreen_yml_components` includes are absent locally and public retrieval was unavailable in preceding checks. This does not establish that Evergreen actually schedules or passes this exact task.

## Required PSMDB change (not implemented)

The test's local diagnostics must not issue aggregate explain inside transaction wrapping. A narrowly scoped guard should skip the final explain-statistics block when `TestData.networkErrorAndTxnOverrideConfig?.wrapCRUDinTransactions` is enabled, in addition to the existing `TestData.inEvergreen` guard. This preserves the useful transactional property test and matches the passing control's effect. Verify the supported configuration indicator against the matching branch before implementation.

If the test is left unchanged, explicitly exclude it in the maintained `buildscripts/resmokeconfig/suites/replica_sets_multi_stmt_txn_jscore_passthrough.yml` selector; derived bulk-write and storage variants should inherit that exclusion. The external list workaround is temporary. Do not enable `TestData.inEvergreen` globally as a workaround, since that changes other test behavior and assertion deadlines.
