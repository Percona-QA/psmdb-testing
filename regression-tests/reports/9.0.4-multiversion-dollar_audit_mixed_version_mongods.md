# dollar_audit_mixed_version_mongods: missing client metadata

**Classification:** Potential missing functionality in Percona audit integration. Reported failure and code-supported hypothesis; not locally reproduced.

PSMDB 9.0.4-1; suites: multiversion, multiversion_future_git_tag.

**Failure:** a missing $impersonatedClient block was reported in the first all-latest profiler-metadata comparison, before old binaries or the Python proxy are used.

**Likely cause:** audit_metadata.cpp adds this block only when AuditClientAttrs exists. No call to resetToPeerClient() was found in the supplied code to initialize these attributes for ordinary external connections. User/role initialization is separate.

**Required investigation:** verify the client decoration at serialization and initialize it at the appropriate connection lifecycle point, preserving forwarded impersonation and proxy addresses. This is a code-supported diagnosis, not a locally reproduced fix.

**Status:** temporarily excluded in both listed suites. No local execution or PSMDB source change.

## Steps to reproduce

These steps describe the reported failure; they were not executed locally.

1. Use PSMDB 9.0.4-1 binaries and the matching test checkout. No old binary is needed for the first scenario.
2. Run the test in its native non-auth suite. The test creates its own users and starts its own sharded cluster with auditDestination console.

```bash
python buildscripts/resmoke.py run --suite=multiversion \
  --jobs=1 --testTimeout=1800 --storageEngine=wiredTiger \
  --storageEngineCacheSizeGB=1 \
  jstests/multiVersion/genericBinVersion/server-security/dollar_audit_mixed_version_mongods.js
```

3. In the first all-latest/FCV 9.0 scenario, inspect the shard profiler entry selected by the test comment. The same failure was also reported in multiversion_future_git_tag.

## Expected and actual

The expected metadata contains the authenticated user/roles and:

```javascript
$impersonatedClient: {
    hosts: [`127.0.0.1:${shellPort}`, `127.0.0.1:${mongosPort}`]
}
```

Reported actual result: the $impersonatedClient block is absent. A complete profiler object was not retained; do not treat the example as a verbatim actual response. Failure precedes the old-binary and load-balanced scenarios, so missing old-version functionality or proxy-protocol is not its immediate explanation.

## Relevant code

src/mongo/rpc/metadata/audit_metadata.cpp adds client data only if this decoration is present:

```cpp
if (auto clientAttrs = AuditClientAttrs::get(opCtx->getClient())) {
    // metadata is constructed here if needed
    metadata->setClientMetadata(clientAttrs->generateClientMetadataObj());
}
```

This is inside the FCV-gated ExposeClientIpInAuditLogs check, enabled at FCV 9.0. User/role metadata is populated separately. src/mongo/rpc/metadata/audit_client_attrs.cpp implements resetToPeerClient() using the session remote/local/proxy endpoints, but no call to it was found in the supplied tree. AuditUserAttrsClientObserver initializes user attributes only. AuditPercona::logClientMetadata logs an event without initializing the client decoration.

Existing client-attribute setters handle incoming impersonation and forwarded operation metadata. They do not explain initialization of a fresh external connection without that metadata. This is the suspected integration gap; absence at runtime has not been instrumented locally.

## Possible fixes and validation

- Confirm the flag/FCV and AuditClientAttrs state on mongos immediately before outgoing metadata serialization.
- Initialize ordinary external-client attributes at the appropriate transport/client lifecycle point. Preserve forwarded impersonation and PROXY-protocol addresses; do not blindly reset attributes on every command.
- Validate both the direct-connection and load-balanced test cases, then the old-FCV cases where the client block is deliberately absent.

Do not remove the expected field or install enterprise modules as a substitute. The server-side serializer is available in PSMDB. No fixed source build or local reproduction has been validated.

## Attribution: Percona audit functionality

PSMDB supplies its own audit implementation where upstream Enterprise adds closed modules. The matching local mongo has identical common metadata serializer/attribute helpers and also has no caller of resetToPeerClient in its available Community tree. That equality does not prove parity of the full audit feature: initialization can belong to the separate audit integration.

The reported missing client-address block is therefore a credible missing-functionality candidate for Percona audit. Trace ordinary-client initialization through AuditPercona and mongos request serialization; closed Enterprise source is not required to check whether the documented/expected Percona behavior is implemented. The specific missing hook remains a hypothesis until its runtime state is inspected. This is not a missing-package prerequisite or a proven defect in the shared serializer.
