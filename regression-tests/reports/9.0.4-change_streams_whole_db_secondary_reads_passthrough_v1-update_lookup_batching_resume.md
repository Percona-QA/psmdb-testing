# update_lookup_batching_resume: no oplog progress with periodic no-ops disabled

**Classification:** Test/configuration mismatch: token-progress assertion requires oplog progress that the no-op-disabled suite does not guarantee. Reproduced with a passing no-op control.

PSMDB 9.0.4-1; suite: change_streams_whole_db_secondary_reads_passthrough_v1.

**Failure:** “resume token never advanced past the batched-but-discarded events”; internal 90-second assertion timeout.

**Cause:** the suite deliberately disables periodic no-ops. Cluster time can advance beyond the secondary’s committed oplog position, and the test assumes further oplog progress without supplying writes.

**Evidence:** baseline FAIL in 93.46 seconds; enabling only periodic no-ops at a one-second interval PASS in 5.22 seconds. This is a test/suite mismatch, not a demonstrated resume-token correctness defect.

**Required fix:** exclude the test through the maintained change_streams matrix mapping/override. Preserve the suite’s intentional no-op configuration.

**Status:** excluded from affected secondary-read entries in the regression list.
