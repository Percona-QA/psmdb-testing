# Exclude update_lookup_batching_resume.js from change_streams_whole_db_secondary_reads_passthrough_v1

## Problem

The suite intentionally leaves periodic no-op writes disabled, but includes a test whose resume-token progress assertion relies on further oplog progress. This causes a timeout unrelated to the batching/resume safety property being tested.

## Environment

- PSMDB version: `9.0.4-1`
- WiredTiger, cache 1 GB, `--jobs=1`
- Test: `jstests/change_streams/update_lookup_batching_resume.js`

## Reproduction

Inside the image, from `/opt/percona-server-mongodb`:

```bash
python buildscripts/resmoke.py run \
  --suite=change_streams_whole_db_secondary_reads_passthrough_v1 \
  --jobs=1 \
  --testTimeout=1800 \
  --storageEngine=wiredTiger \
  --storageEngineCacheSizeGB=1 \
  jstests/change_streams/update_lookup_batching_resume.js
```

## Actual result

The first test case passes. The second case, “advances the resume token once batched-but-non-matching events are exhausted,” fails after its internal 90-second deadline:

```text
assert.soon failed (timeout 90000ms):
resume token never advanced past the batched-but-discarded events
```

The test completed with failure after 93.46 seconds. Fixture setup, validation and teardown passed.

## Analysis

The suite mapping applies `change_streams.disable_write_noops`. This override removes `writePeriodicNoops` and `periodicNoopIntervalSecs` from fixture parameters. Runtime inspection confirmed `writePeriodicNoops=false`.

The test captures `endTime = getClusterTime(db)` and waits for the resume-token timestamp to reach it. However, cluster time can advance beyond the committed oplog position available on the secondary. `FixtureHelpers.awaitLastOpCommitted(db)` waits for existing oplog entries to become committed; it does not guarantee further oplog progress to the captured cluster time.

Without subsequent writes or periodic no-ops, the assertion can wait until its deadline. This is a test/suite compatibility issue, not evidence of a server resume-token correctness defect.

## Control run

Repeating the same test with:

```text
--mongodSetParameters='{writePeriodicNoops: true, periodicNoopIntervalSecs: 1}'
```

passed both test cases in 5.22 seconds, with all hooks passing.

`featureFlagChangeStreamOptimizedUpdateLookup` was disabled in the baseline; the failure therefore does not require optimized batching to be enabled.

## Required change

Explicitly exclude:

```text
jstests/change_streams/update_lookup_batching_resume.js
```

from `change_streams_whole_db_secondary_reads_passthrough_v1`.

Maintain the exclusion through:

- `buildscripts/resmokeconfig/matrix_suites/mappings/change_streams_whole_db_secondary_reads_passthrough_v1.yml`
- A narrowly scoped exclusion definition in `buildscripts/resmokeconfig/matrix_suites/overrides/change_streams.yml`

Regenerate the effective matrix configuration using the target branch's supported procedure. Do not hand-edit only the generated YAML.

Preserve the suite's intentional no-op configuration. Enabling periodic no-ops for the entire suite is a diagnostic workaround that changes its execution conditions.

Inspect related suites for the same incompatibility before extending the exclusion; they were not validated by this reproduction.

## Acceptance criteria

- The effective suite configuration explicitly excludes this test.
- Periodic no-op settings remain unchanged.
- The test remains available in compatible suites.
- Maintained matrix sources and regenerated configuration agree.

## Evidence limits

The matching PSMDB branch and public upstream mapping both contain `disable_write_noops`. Full upstream Evergreen task/variant arguments could not be verified because included configuration files were unavailable and the project API required authentication.

Only the named test was executed, not the full suite. No PSMDB files were changed during diagnosis.
