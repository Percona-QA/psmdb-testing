# draining_on_FCV_transition: blocker created after the barrier

**Classification:** Shared test/protocol synchronization defect. Reproduced with a passing legacy-protocol control; matching upstream test, FCV command and flag definitions are identical.

PSMDB 9.0.4-1; suite: multiversion.

**Failure:** final FCV 9.0-to-8.0 transition returns ok:1 instead of LockTimeout with a prepared transaction.

**Cause:** default-on featureFlagSymmetricFCV executes final draining before hangBeforeUpdatingFcvDoc. The test creates its transaction only after reaching that failpoint, too late to block the barrier. The baseline log confirms this ordering. Only latest binaries are used.

**Evidence:** default settings FAIL in 1.41 seconds; changing only featureFlagSymmetricFCV to false makes the complete test PASS in 14.29 seconds.

**Required fix:** synchronize blocker creation before the actual final barrier. Review other scenarios sharing that helper. Do not disable Symmetric FCV for the whole suite as the fix.

**Status:** remains enabled; PSMDB source and suite list unchanged.

**Matched-version attribution:** `jstests/multiVersion/genericSetFCVUsage/fcv_core/draining_on_FCV_transition.js` match the version-matched local mongo checkout byte-for-byte. No PSMDB-specific difference is established by these files. Earlier moving-master differences are not the comparison baseline for this release.
