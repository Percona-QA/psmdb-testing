# extensions_query_stats: shell HMAC uses an empty key

**Classification:** Shared shell-source defect exposed by the tested binary/toolchain. Non-empty-key HMAC is wrong; the complete helper implementation is identical in matched mongo. No Percona-specific HMAC implementation is involved.

PSMDB 9.0.4-1; reproduced in extensions_standalone.

**Failure:** expected eight transformed queryStats entries, received zero; baseline FAIL in 10.20 seconds.

**Cause:** src/mongo/shell/shell_utils.cpp constructs std::string(binData(keySize), keySize). Argument evaluation can read keySize before binData populates it, producing an empty key. The shell digest exactly matched an independent empty-key HMAC rather than the supplied-key digest.

**Evidence:** replacing only the expected-HMAC calculation with Python’s keyed HMAC made the entire test PASS in 2.20 seconds. This validates the cause, not a rebuilt C++ fix.

**Required fix:** extract the binary pointer and size in one statement, then construct the string in a separate statement. Rebuild the shell and validate against a non-empty-key HMAC vector and the unmodified test.

**Status:** temporarily excluded from extensions_* entries; other topologies were not executed.

**Matched-version attribution:** `src/mongo/shell/shell_utils.cpp` match the version-matched local mongo checkout byte-for-byte. No PSMDB-specific difference is established by these files. Earlier moving-master differences are not the comparison baseline for this release.
