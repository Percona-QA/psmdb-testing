# extensions_query_stats: mongo shell computes HMAC with an empty key

## Confirmed cause

`computeSHA256Hmac()` in the supplied mongo shell uses an empty HMAC key instead of the provided non-empty key. Consequently, `extensions_query_stats.js` computes the wrong hashed collection name and filters all entries out of a correctly transformed `$queryStats` response.

The failure is in the shell utility, not the test extensions or the server queryStats implementation. Correcting only the expected-HMAC calculation in a disposable copy of the JS test makes the entire test pass.

## Environment and baseline

- PSMDB version: `9.0.4-1`.
- Suite: `extensions_standalone`.
- Test: `jstests/extensions/extensions_query_stats.js`.
- Docker: 2 CPUs, 8 GiB RAM; sequential runs.
- Arguments: `--installDir /usr/bin --jobs=1 --storageEngine=wiredTiger --storageEngineCacheSizeGB=0.25 --testTimeout=1800 --skipExtensionsSignatureVerification --mongodSetParameters='{featureFlagExtensionsApiSignatureValidation: false}'`.
- Extensions built successfully inside Docker with `bazel build --config=psmdb_opt_release //:install-extensions --define=MONGO_VERSION=9.0.4-1 --jobs=2 --local_ram_resources=4096`.

The unmodified test failed in 10.20 seconds, resmoke exit code 1, with the exact supplied failure:

```
Error: expected 8 to equal 0
runQueryStatsTest@jstests/extensions/extensions_query_stats.js
@jstests/extensions/extensions_query_stats.js
```

This is the first identifier-transformation scenario, `transformed identifiers (Caroline)`. Seven preceding shape checks succeeded. The test expects eight entries, but the match on the incorrectly hashed collection name returns zero.

## Independent HMAC verification

Payload: `diagnostic_collection`.
Key: the test's `kDefaultQueryStatsHmacKey`, sensitive BinData with base64 contents `MjM0NTY3ODkxMDExMTIxMzE0MTUxNjE3MTgxOTIwMjE=`.

| Calculation | Base64 digest |
|---|---|
| Current mongo shell `computeSHA256Hmac()` | `3fJQvOd6zVcC9rY+EoNb7i239qW0tjQcnK3cYsQzXPo=` |
| Independent Python HMAC with the supplied key | `9gMj4Ut9BWFgJLtippBiFzXkdcqNzvx7LyAnxwCnMyU=` |
| Independent Python HMAC with an empty key | `3fJQvOd6zVcC9rY+EoNb7i239qW0tjQcnK3cYsQzXPo=` |

The shell result exactly equals the empty-key reference.

## Code defect and required PSMDB fix

File: `src/mongo/shell/shell_utils.cpp`.

Current code:

```cpp
int keySize = 0;
std::string key = std::string(cmdObj[kComputeSha256HmacKeyField].binData(keySize), keySize);
```

The constructor arguments have no guaranteed evaluation order. The length argument can be read while `keySize` is still zero, before `binData(keySize)` populates it. The current binary's output confirms that this produces an empty key in this environment.

Separate pointer/length extraction from string construction:

```cpp
int keySize = 0;
const char* keyData = cmdObj[kComputeSha256HmacKeyField].binData(keySize);
std::string key(keyData, keySize);
```

Add a meaningful regression check against a known non-empty-key HMAC vector, ideally including distinct keys for the same payload. Rebuild the affected shell and rerun the unmodified extension queryStats test to validate the actual source fix. No source fix or shell rebuild was performed in this investigation.

## Causality control

A second clean container reused the exact extension libraries from the baseline build. The only test change was replacing the body of `fetchHmac(payload)` with an independent Python `hmac`/`hashlib.sha256` calculation using the original key. Server binary, extensions, test scenarios and execution settings stayed the same.

Result: the entire JS test passed in **2.20 seconds**, resmoke exit code **0**. Fixture setup, validation hooks and teardown passed too. Resmoke reported five passing execution entries; these represent one JS test plus infrastructure/hook entries, not five separate JS tests.

This verifies the cause, not the proposed C++ fix itself. A temporary test workaround is not a substitute for correcting the shell utility.

## Applicability

Only the standalone suite was executed. Other `extensions_*` topologies were not run; they select the same test and use the same shell utility, but their full execution is not claimed as validated.

Exact upstream Evergreen task/variant settings remain unavailable because the referenced component configuration files are absent from the checkout. Available suite definitions and launch code were inspected.
