# Product-limits explain exceeds BSON nesting depth

Environment: PSMDB 9.0.4-1.

`query_limits_test.js` in `product_limits` — **Test/explain-limit mismatch** — the recorded run fails in `DatasetManyCollections.WorkloadManyCollectionsLookupBushy`. Its explain plan exceeds the BSON nesting limit, but the workload helper accepts only a BSON size-limit error.

## Evidence

The supplied run completed after 1766.80 seconds with resmoke exit code 1 and shell exit code 253. The decisive error was:

```text
BSONObj exceeds maximum nested object depth
stages.0.$cursor.queryPlanner.winningPlan.queryPlan.inputStages.0.inputStages.0...
```

`jstests/product_limits/libs/long_pipelines.js` constructs 499 `$lookup` stages followed by `$unset` for this workload. The server logged the explain response after 4169 ms with `reslen: 805937`; this is below the 16 MB BSON size limit. The reported failure concerns nesting depth, not response size, RAM exhaustion or expiration of the 1800-second timeout.

In `jstests/product_limits/libs/workload.js`, the preliminary `explain("allPlansExecution")` is wrapped in a catch block containing:

```javascript
jsTest.log.info({codeName: error.codeName});
assert(error.code === ErrorCodes.BSONObjectTooLarge, error);
```

The captured exception has `codeName: undefined` and fails that assertion. The actual aggregate and result comparison for this workload are after the explain block and were not reached. The full test sequence, including later datasets, was not completed. No additional local reproduction or control was run for this investigation.

## Required investigation and proposed PSMDB change

Handle the specific explain nesting-depth failure separately from BSON size overflow in the maintained workload helper, while retaining execution and result validation of the actual aggregate. Determine how the shell exposes this exception before choosing a narrow error check; do not suppress arbitrary explain errors. Alternatively, reduce the explain workload's scale while preserving the intended limits coverage. Neither approach has been validated.

The suite explicitly enables join optimization and CBR/samplingCE. The required workload/helper code matches the local mongo baseline; no Percona-specific defect was established. Actual Evergreen task/variant arguments and resource settings could not be verified because the included components are absent locally and corresponding public target-version paths returned HTTP 404.

## Status

`product_limits` is temporarily disabled in the regression list. Re-enable after a targeted explain-limit handling change is validated and the actual aggregate/result comparison completes. Increasing RAM, cache or the timeout is not a demonstrated fix for the observed depth failure. No PSMDB source was changed.
