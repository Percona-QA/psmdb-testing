# Config-server replica-set suite: infinite fixture setup retry, not a hook hang

## Confirmed result

With the unmodified suite, execution never reaches the selected JS test or background hooks. Fixture setup repeatedly fails while adding the second replica-set member:

```
Nodes started with the --configsvr flag must have configsvr:true in their config
code: 103 (NewReplicaSetConfigurationIncompatible)
```

There were 665 retries in the captured baseline log before the diagnostic run was stopped. The baseline was interrupted, not completed or reported as a JS-test failure.

A fresh control run adding only `executor.fixture.replset_config_options.configsvr: true` inside a disposable container completed successfully in 7.04 seconds. The selected `insert1.js` ran in 0.79 seconds. All configured hooks passed.

This disproves the hook-hang hypothesis for this reproduced case. It provides a concrete mechanism for a multi-hour run without test progress. The user's current Jenkins log was not available, so matching that exact running job requires checking for the same repeated setup error.

## Environment and command

PSMDB version: `9.0.4-1`.
Docker limits: 2 CPUs, 8 GiB RAM. Cache settings were left as in the suite-list entry; no explicit storage/cache flag was added. Logs show `cache_size=3584M` per mongod.

```bash
python buildscripts/resmoke.py run   --suite replica_sets_configsvr_param_jscore_passthrough   --jobs=1 --testTimeout=1200 --continueOnFailure   --reportFile=/work/report.json   jstests/core/write/insert/insert1.js
```

The chosen test is an ordinary short insert test under the suite's `jstests/core/**/*.js` root. Both runs used the same test, binary, hooks and resource/cache settings.

## Root cause

The suite sets `mongod_options.configsvr` but does not set `replset_config_options.configsvr`.

`ReplicaSetFixture.setup()` constructs the replica-set configuration from `replset_config_options`. It adds `configsvr: true` only when explicitly requested there (or in a separate auto-bootstrap case), not merely because mongod was launched with `--configsvr`.

The first single-member initiation succeeds, but the locally constructed configuration used when adding the second member lacks `configsvr: true`. The server rejects that reconfiguration.

`ReplicaSetFixture._reconfig_repl_set()` retries code 103 in an unbounded `while True`, sleeping 0.1 seconds between attempts. This error is permanent for the unchanged configuration, so the retry does not resolve it.

The 1200-second per-test timeout does not protect this fixture-setup path. The observed baseline remained in `job0_fixture_setup_0`; `insert1.js` never started.

## Required PSMDB changes (proposed, not implemented)

In `buildscripts/resmokeconfig/suites/replica_sets_configsvr_param_jscore_passthrough.yml`, retain the existing `--configsvr` launch option and add:

```yaml
executor:
  fixture:
    class: ReplicaSetFixture
    replset_config_options:
      configsvr: true
    mongod_options:
      configsvr: ""
      set_parameters:
        enableTestCommands: 1
    num_nodes: 2
```

This is the exact minimal configuration change validated by the control; no hooks were removed or disabled.

Separately, bound retries or distinguish permanent configuration errors in `buildscripts/resmokelib/testing/fixtures/replicaset.py`, `_reconfig_repl_set()`. Treating every code-103 response as indefinitely transient conceals this fixture defect as a long-running suite.
