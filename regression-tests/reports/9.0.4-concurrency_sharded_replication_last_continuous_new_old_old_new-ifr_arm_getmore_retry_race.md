# ifr_arm_getmore_retry_race: persistent queries on old mongos

**Classification:** Unresolved mixed-version router hang. Reproduced on old mongos; current matching test identity does not establish the old server’s root cause or Percona-specific attribution.

PSMDB 9.0.4-1 with PSMDB 8.3.11-3; suite: concurrency_sharded_replication_last_continuous_new_old_old_new.

**Failure:** query/ifr_arm_getmore_retry_race.js timed out after 1200.19 seconds. find/getMore operations remained blocked on old mongos across repeated samples while background hooks continued. Later shutdown-hook errors followed timeout recovery.

**Evidence:** the other four selected workloads passed, including analyze_shard_key, reshard_collection_crud_ops and both internal-transaction candidates. The old mongos retry path differs, but the precise C++ cause and correspondence to the reported Jenkins hang remain unproven.

**Required investigation:** inspect the old mongos ARM retry path and maintain a narrow affected-configuration exclusion pending compatibility validation. Related context: SERVER-133148 / BACKPORT-29703; neither proves the local root cause.

**Fixture control:** a separate count/count.js execution passed in 3.03 seconds; its fixture, hooks and teardown completed in 10.87 seconds. No general setup/hook hang was reproduced by that control. Diagnosis used the local multiversion-tag wrapper after the then-configured download URL failed; that preparation issue is separate from the reproduced IFR runtime hang.

**Status:** the affected suite is disabled in the regression list. No latest-only control was run; no enterprise dependency was established.

**Matched-version attribution:** `jstests/concurrency/fsm_workloads/query/ifr_arm_getmore_retry_race.js` match the version-matched local mongo checkout byte-for-byte. No PSMDB-specific difference is established by these files. Earlier moving-master differences are not the comparison baseline for this release.
