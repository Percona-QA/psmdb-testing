## Potential PSMDB and percona-mongot bugs

### Tests

- `dollar_audit_mixed_version_mongods.js` in `multiversion`, `multiversion_future_git_tag` — **Audit integration candidate** — The existing exclusion concerns missing $impersonatedClient.hosts. rpc/metadata/audit_metadata.cpp serializes this field only when AuditClientAttrs exists; initialization in the Percona audit path needs checking. This was established for another release, not reproduced on 8.3. It remains excluded pending version-specific verification.

- `ranked_and_score_fusion_scoreDetails_metadata.js` in `mongot_community_fixture_e2e_sharded_collections` — **Potential search-index readiness gap** — Reproduced with PSMDB 8.3.17-5 and percona-mongot 1.70.3: the first $rankFusion returns one document instead of two, before scoreDetails structure is checked. A disposable control adding a five-second delay after createSearchIndex passed the complete test. This supports a gap between index queryability and visibility of the expected documents, but one control does not establish the exact cause or a production fix. Remains enabled pending investigation of indexing readiness and result visibility.

- `ranked_fusion_on_search_view.js` in `mongot_community_fixture_e2e_sharded_collections`, `mongot_community_fixture_e2e_single_node` — **Potential index-drop visibility race** — With PSMDB 8.3.17-5 and percona-mongot 1.70.3, the unmodified sharded test passed in 18.52 seconds; the single-node test failed when equivalent collection/view queries produced 50 versus zero documents after the imported helper dropped its search indexes. A disposable single-node control adding a five-second delay after the helper drops passed. This supports delayed deletion visibility, but one control does not isolate the causal implementation path or establish a production fix. Both suites retain the test pending investigation.

## Disabled: established reasons
